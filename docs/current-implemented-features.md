# 火炬电子研发知识库项目当前实现功能说明

> 编写口径：依据《火炬电子研发知识库项目-实施范围确认书 V1.2》和当前代码实现整理。  
> 本文只说明当前已实现或已接入的功能范围；详细实施方案见 `docs/plans/`。
> 最后更新：2026-07-06，对应已提交的 B1/B2 代码能力。

## 1. 当前系统总体能力

当前项目已经形成一条从研发文档入库到知识库问答，再到基于历史文档生成新文档草稿、编辑现有文档模块的主流程：

1. 阶段一 A→B：非结构化文档上传、格式转换、PDF/VLM 解析、结构化建树、索引入库、文档管理、问答检索、原文溯源。
2. 阶段二 B→A：已纳入 B1“基于历史文档框架生成新文档草稿”和 B2“现有文档模块级编辑”。
3. 前端当前由后端直接服务单页界面，承载文档上传、文档列表、文档结构查看、重新解析、聊天问答、B1 文档生成和 B2 模块编辑入口。

系统后端采用 FastAPI，业务模块按 `ingest`、`chat`、`docgen`、`docedit` 等 feature-first 方式组织；解析、PageIndex、混合检索、文档读取等基础能力放在 `app/core`。

## 2. 阶段一 A→B：文档入库与知识库问答

### 2.1 文档上传与格式转换

当前支持通过入库接口上传研发资料，PDF 文档直接进入解析流程；Word、Excel、PPT、TXT、RTF、ODT、CSV 等格式先通过 Gotenberg/LibreOffice 转换为 PDF，再复用统一 PDF 管线。

已接入能力包括：

- 单文件上传与任务创建。
- 多格式文档转 PDF 后入库。
- 原始 PDF 保存，用于后续查看、溯源和重新解析。
- 入库任务状态查询。
- 上传后的文档进入解析、建树、索引流程。

当前格式转换的核心边界是：系统不还原原始 Word 的复杂物理排版，也不自动编辑流程图、图形控件或复杂嵌入对象。

### 2.2 PDF/VLM 解析

当前 PDF 解析走纯 VLM 管线，主要阶段包括：

- 页面渲染。
- Phase 1：识别页面结构和标题候选。
- Phase 1.5：对标题层级进行整体校正。
- Phase 2：并行页面内容转换为 Markdown，并修复跨页续接。
- 后处理：合并 Markdown、校验结构、生成页码映射等产物。

解析过程中保留 `<notsure>...</notsure>` 标记机制，用于标记模型不确定内容，后续进入人工审核流程。

当前代码中已不再保留独立的 Phase 2.5 阶段，相关处理已并入现有解析和后处理流程。

### 2.3 文档结构化与建树

解析后的 Markdown 会进入 PageIndex 建树流程，将文档拆成适合检索和展示的树形结构。当前文档结构主要面向以下用途：

- 前端“文档结构”视图展示章节、段落和节点内容。
- 聊天检索时按目录、节点和片段定位信息。
- 原文溯源时回到具体文档节点。
- B1 文档生成时读取历史文档框架和节点内容。

文档结构主要由解析后的标题层级、正文内容和建树算法共同决定。解析质量、标题层级识别质量、摘要/节点内容质量都会影响前端文档结构的可读性和后续检索效果。

### 2.4 向量与混合检索索引

当前检索方案是 PageIndex 树形检索加 BM25/向量混合检索：

- BM25 作为基础检索能力。
- 向量检索作为增强项。
- 通过 RRF 等融合方式综合排序。
- 当 embedding 不可用时，系统可以退回到纯 BM25 检索。

索引构建后，聊天模块可以通过工具读取目录、打开节点、读取节点正文和搜索节点。

### 2.5 人工审核

当解析结果中存在不确定内容时，系统会生成待审核记录。当前已接入的能力包括：

- 查看待审核文档列表。
- 查看单个文档的待审核内容。
- 对待审核内容进行确认。
- 审核通过后继续推进后续入库流程。

人工审核的目标是让 VLM 不确定内容在入库前被显式确认，避免不确定文本直接污染知识库。

### 2.6 文档管理

当前文档管理能力包括：

- 查看知识库文档统计。
- 查看文档列表和任务状态。
- 查看单个文档详情。
- 查看文档树结构。
- 查看原始 PDF。
- 删除文档。
- 对已入库文档发起重新解析。

重新解析功能会复用历史原始 PDF，重新跑完整入库链路。系统会为重新解析创建任务，并在新结果可提交前尽量保留旧文档可用，避免重新解析失败时直接破坏当前可用知识库。

### 2.7 自然语言问答

当前聊天模块已经接入知识库检索工具，支持围绕入库文档进行自然语言问答。主要能力包括：

- 普通聊天接口。
- 流式聊天接口。
- 按知识库范围过滤检索。
- 读取文档目录和节点内容。
- 在文档节点中搜索相关内容。
- 查询结果带来源信息，便于用户继续查看原文。

对于“思考过程”和“横向比较”类需求，当前主要通过聊天 Agent、检索工具和大模型推理实现。系统可以支持问答式比较，但当前没有单独实现一个独立的“横向比较配置表”或专门的对比分析模块。

### 2.8 原文溯源

当前系统支持从问答结果或文档结构回到原始文档内容。溯源信息主要包括：

- 文档 ID 和文档名称。
- 节点标题、章节路径或树节点位置。
- 对应 Markdown 节点内容。
- PDF 查看入口和页码映射能力。

系统当前更强调“章节/节点级定位”和 PDF 查看，不承诺还原 Word 原始物理页码和原始排版位置。

### 2.9 前端界面

当前前端以单页原型方式由后端服务，已经覆盖核心使用流程：

- 上传文档。
- 查看入库任务。
- 查看文档列表。
- 打开文档结构。
- 查看 PDF。
- 对文档发起重新解析。
- 进入聊天问答。
- 使用 B1 文档生成功能。
- 在文档结构弹窗中使用 B2 模块级编辑功能。

该界面目前是项目主使用入口，不是独立的 Next.js 前端工程。

## 3. 阶段二 B→A：文档生成与模块编辑

当前阶段二包含两条能力：

- B1：基于历史文档框架生成新文档草稿。
- B2：在已有知识库文档中定位具体模块，并编辑该模块自己的正文。

### 3.1 B1：基于历史框架生成新文档

#### 3.1.1 选择历史蓝本文档

当前 B1 功能可以从已入库文档中选择历史文档作为蓝本。系统会读取该文档的目录、结构和节点内容，用于后续生成新文档草稿。

#### 3.1.2 蓝本摘要与需求澄清

创建文档生成会话后，系统会基于所选蓝本文档生成摘要，并结合用户输入的目标需求进行分析。当前实现会保存生成会话，后续计划和草稿都围绕同一个会话推进。

#### 3.1.3 生成改动计划

系统会基于蓝本文档内容、用户需求和检索结果生成结构化改动计划。计划项中会区分：

- 用户明确指定的修改。
- AI 根据上下文推理出的修改。
- 需要计算或校验的数值项。
- 可能存在风险或需要人工确认的项。

用户可以对计划项进行选择或取消选择，决定哪些内容进入最终草稿。

#### 3.1.4 生成新文档草稿

当前草稿生成逻辑以历史 Markdown 文档为基础，对被选中的计划项进行确定性替换，生成新的 Markdown 草稿。返回内容包括：

- 草稿 Markdown。
- 便于复制的正文内容。
- 带高亮信息的 Markdown。
- 修改位置和替换范围等元数据。

该流程不会直接覆盖原知识库中的已入库文档，也不会自动更新 PageIndex 或检索索引。

#### 3.1.5 当前输出边界

B1 当前重点是生成可复制、可审阅的结构化草稿。当前不承诺：

- 自动生成并下载 DOCX。
- 还原历史 Word 的复杂样式、页眉页脚、批注或嵌入对象。
- 自动写回原始 Word 文件。
- 自动替换知识库中的正式文档。

### 3.2 B2：现有文档模块级编辑

B2 当前通过“知识库 > 文档结构”弹窗接入，不新增独立页面。管理员打开某个文档结构后，可以选择具体节点，查看该节点自己的正文，并进行手动编辑或 AI 辅助编辑。

#### 3.2.1 编辑状态与权限

当前 B2 通过 `docedit` 模块提供文档级编辑状态：

- 文档当前版本号。
- 当前账号是否可编辑。
- 是否存在正在进行的重新解析任务。
- 哪些节点已经被修改过。

权限仍是 v0 开发占位实现：`auth.dependencies` 返回配置中的开发用户，`DEV_AUTH_IS_ADMIN=true` 时本地默认是管理员。正式登录、用户管理和 RBAC 仍未完成。

#### 3.2.2 节点读取与可编辑判断

B2 编辑目标是节点自己的正文，不编辑标题、层级、子节点或 PDF 原文。当前可编辑判断包括：

- 管理员才可保存、AI 编辑或回退。
- 纯容器节点不可编辑。
- 没有正文的节点不可编辑。
- 正在重新解析的文档不可编辑。
- 合并窗口节点默认只读；前端会列出具体物理片段，用户选择“编辑这一段”后才编辑单个片段。

#### 3.2.3 手动保存

手动保存会校验：

- `base_version`：防止文档级版本冲突。
- `base_hash`：防止节点正文已经被别人改过。
- active reparse：同一文档重新解析期间禁止编辑。
- 当前节点仍然存在且正文块能和 Markdown 精确对应。

保存后会同步更新：

- `backend/data/md/` 中的 Markdown 正文。
- `backend/data/workspace/` 中的 PageIndex workspace JSON。
- `backend/data/catalog/` 文档目录。
- `backend/data/indexes/` BM25/向量检索索引。
- `.pagemap.json` 行号映射。
- 数据库中的文档版本、节点改动状态和历史记录。

写文件和重建索引使用快照保护。如果文件写入/索引发布成功但数据库提交失败，会恢复 Markdown、workspace、catalog、pagemap、domain_dict 和 indexes，避免正式知识库出现半更新状态。

#### 3.2.4 AI 辅助编辑

AI 编辑复用 `CHAT_MODEL` 和 LiteLLM Proxy。接口只读取当前节点自己的正文，根据用户指令返回：

- 修改后的正文。
- 修改说明。
- 红删绿增的 diff HTML。

AI diff 只做预览，不直接落盘。用户确认后仍走同一个保存接口，保存时再次进行版本/hash 校验。

#### 3.2.5 历史记录与回退

B2 历史是文档级时间线，不是节点级版本库。每次保存会记录：

- 修改前/后的正文。
- 修改前/后的 hash。
- diff HTML。
- 操作类型：手动、AI、回退。
- 操作人占位信息。
- 节点标题和路径。

回退不会删除旧历史，而是追加一条新的回退记录，并把正文恢复到目标历史版本的内容。

#### 3.2.6 当前边界

B2 当前不承诺：

- 修改标题、章节层级或子节点结构。
- 重新跑 PDF/VLM 解析。
- 重建完整 PageIndex 树摘要。
- 自动同步修改原始 PDF 或 Word。
- 解决正式 RBAC、登录和审计闭环。

## 4. 数据与产物

当前系统运行过程中会产生以下主要数据和文件产物：

- 原始 PDF：用于查看、溯源和重新解析。
- 解析 Markdown：作为结构化建树和草稿生成的基础文本。
- PageIndex 工作区 JSON：保存文档树结构。
- 文档目录 catalog：记录已入库文档及其元信息。
- 检索索引：用于 BM25/向量混合检索。
- 入库任务记录：保存上传、解析、建树、索引、重新解析等任务状态。
- 待审核记录：保存解析不确定内容和人工确认状态。
- B1 文档生成会话：保存蓝本文档、需求、改动计划和草稿结果。
- B2 文档编辑状态：保存文档版本、节点改动状态、修改历史和回退记录。

## 5. 接口能力概览

当前后端已接入的主要接口能力包括：

| 模块 | 能力 |
|---|---|
| `ingest` | 文档上传、格式转换、任务查询、审核、建树、索引、文档详情、文档树、PDF 查看、删除、重新解析 |
| `chat` | 普通聊天、流式聊天、节点内容读取、知识库检索、来源定位 |
| `docgen` | 蓝本文档列表、创建生成会话、生成改动计划、调整计划、生成草稿 |
| `docedit` | 文档编辑状态、节点可编辑正文读取、手动保存、AI diff、修改历史、回退 |

## 7. 当前不纳入本文的范围

以下内容当前尚未作为正式能力完成：

- 自动生成正式 DOCX 文件。
- 自动回写或修改原始 Word 文件。
- Word 原始物理页码、版式、页眉页脚、批注和复杂对象的完整还原。
- 工作流审批系统。
- 独立移动端。
- 完整账号、角色、MAC 绑定等权限体系的最终交付说明。
- B2 保存后的祖先 summary 异步重生成。
